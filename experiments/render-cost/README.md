# 렌더가 왜 47초나 걸렸나

**CPU 가 느려서가 아니라, 쓰지도 않을 장면을 잔뜩 그리고 있었습니다.**
재서 원인을 찾고 고쳤습니다 (2026-10-20). 결과부터 적습니다.

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 렌더 시간 | **30~47초** | **8초** |
| 나오는 영상 | 16.8초 (2.4배 느림) | 0.5초 · 1.7초 (제 속도) |
| MP4 크기 | 695KB | 17KB · 82KB |

## 1. 렌더 시간은 프레임 수에 비례합니다

`measure.py` 가 같은 그림 · 같은 동작으로 **그리는 프레임 수만** 바꿔 가며 잽니다.
Meta 예제 캐릭터를 쓰므로 **모델 서버(TorchServe)는 필요 없습니다.**

```powershell
docker compose build ai
docker run --rm -v "${PWD}:/repo" -w /repo drawtale-ai-ai:latest `
  python experiments/render-cost/measure.py
```

20코어 PC 에서 나온 값입니다.

| 그린 프레임 | 걸린 시간 |
|---|---|
| 37 | 6~8초 |
| 237 | 11.4초 |
| **839** | **30.6초** |

→ **고정 5초 + 프레임당 0.03초**

고정 5초는 그물 만들기 · 그래픽 초기화 · 영상 인코딩처럼 프레임 수와 상관없는 몫입니다.
장면마다 렌더를 새로 부르니 이 5초는 장면 수만큼 듭니다. **이건 못 줄였습니다.**

## 2. 그런데 839프레임을 왜 그리고 있었나

쓰는 동작 파일이 **초당 120프레임**으로 기록돼 있었습니다.

```
wave_hello_gentle.bvh   839프레임 ÷ 120fps = 실제 동작 7.0초
jumping_gentle.bvh      654프레임 ÷ 120fps = 실제 동작 5.5초
```

그런데 설정에는 `end_frame_idx: 839` 가 적혀 있어서 **한 장도 안 빼고 다 그렸습니다.**

문제가 하나 더 있었습니다. Meta 는 GIF 로 먼저 뽑는데 **GIF 는 한 프레임을 20ms 보다
짧게 둘 수 없습니다.** 120fps 는 8ms 라서 20ms 로 밀려 올라갑니다.

```
839프레임 × 20ms = 16.8초 영상   (실제 동작은 7.0초)
```

**즉 2.4배 느린 슬로모션이 나오고 있었습니다.** 느리게 그리느라 오래 걸리고, 결과도 느렸습니다.

## 3. 어디를 남길지는 재서 골라야 합니다

「앞 3초만 쓰자」가 맞을 것 같았는데 **정반대**였습니다.
손 위치를 프레임마다 뽑아 보니 손흔들기는 이렇습니다.

```
0.0 ~ 3.4초   손을 옆에 들고 가만히      ← 앞 3초는 여기
3.4 ~ 4.9초   올려서 흔듭니다            ← 쓸 구간
4.9 ~ 7.0초   내리고 가만히
```

그리고 프론트는 장면 영상을 `<video loop>` 로 **반복 재생**합니다
(프론트 저장소 `src/screens/S09Story.tsx`). 그래서 **영상 길이를 음성 길이에 맞출 필요가 없습니다.** 짧으면 반복됩니다.
대신 **첫 자세와 끝 자세가 비슷해야** 반복할 때 안 튑니다.

`pick_window.py` 가 (시작, 끝) 짝마다 **이음새**(첫·끝 자세 거리)와 **움직임**(구간 안에서
관절이 움직인 양)을 재서, 움직임이 충분한 것 중 이음새가 가장 작은 구간을 알려 줍니다.

```powershell
docker run --rm -v "${PWD}:/repo" -w /repo drawtale-ai-ai:latest `
  python experiments/render-cost/pick_window.py `
    runtime/ai_server/motions/wave_hello_gentle.bvh 손흔들기 0.5 2.5
```

고른 구간입니다.

| 동작 | 구간 (원본 프레임) | 길이 | 이음새 | 무슨 동작인가 |
|---|---|---|---|---|
| `wave_hello` | 465~524 | 0.49초 | **0.52** | 든 손을 한 번 흔들기 |
| `jumping` | 218~426 | 1.74초 | 1.40 | 웅크렸다 뛰고 착지해서 다시 서기 |

손흔들기는 **한 주기만** 잡았습니다. 두 주기(0.98초)는 이음새가 1.06 으로 나빠집니다 —
팔이 내려오는 중이라 자세가 점점 달라지기 때문입니다. 한 주기를 반복하면 계속 흔드는 모습이 됩니다.

## 4. 반복 이음새가 실제로 안 튀는지 확인

관절 좌표로 잰 이음새가 작아도 눈에 띌 수 있으니 **그려진 그림으로** 다시 봅니다.
`check_seam.py` 가 마지막 → 첫 프레임 차이를 보통 프레임 사이 차이와 비교합니다.

```
wave_hello_gentle   프레임 15개   프레임 사이 평균 0.95 최대 1.64   이음새 1.52 (1.6배)
jumping_gentle      프레임 52개   프레임 사이 평균 4.68 최대 9.43   이음새 7.12 (1.5배)
```

둘 다 **이음새가 가장 큰 프레임 차이보다 작습니다.** 동작 안에서 원래 일어나는 변화보다
작게 넘어가니 반복해도 눈에 안 띕니다.

## 5. 고친 자리

[`runtime/tools/make_gentle_motions.py`](../../runtime/tools/make_gentle_motions.py) 에
두 단계를 넣었습니다. 팔 순화는 그대로입니다.

1. **구간 자르기** — `CLIPS` 에 적은 범위만 남깁니다
2. **프레임 솎기** — 120fps 를 30fps 로 (네 프레임 중 하나). 한 프레임이 33ms 라
   GIF 의 20ms 한계에 걸리지 않아 **제 속도로 재생**됩니다

```powershell
docker compose run --rm -v "${PWD}:/repo" -w /repo ai `
  python runtime/tools/make_gentle_motions.py
```

```
wave_hello_gentle: 15 frames, 30fps, 0.50s
jumping_gentle: 52 frames, 30fps, 1.74s
```

## 6. 아직 안 한 것

- **같은 그림 + 같은 동작 다시 쓰기.** 미리보기(S-05)에서 이미 한 번 그리는데 버립니다.
  그림 해시와 동작 이름을 키로 두면 되는데 아직 없습니다
- **미리 그려 두기.** 아이가 행동 카드 고르는 동안 뒤에서 그려 두면 체감 0초가 되지만,
  안 쓸 것까지 그려서 서버 일이 늘어납니다. 교실에서 동시에 쓰는 걸 재 본 다음에 볼 일입니다
- **고정 5초 줄이기.** 장면마다 렌더를 새로 부르니 그물과 그래픽 초기화를 매번 다시 합니다.
  Meta 엔진이 한 번에 여러 동작을 돌리는 구조가 아닙니다
- 15fps 까지 더 낮추는 것은 **하지 않기로 했습니다.** ① 뒤에는 8초가 6.4초 되는 정도인데
  움직임이 끊겨 보일 위험을 질 만한 값이 아닙니다
