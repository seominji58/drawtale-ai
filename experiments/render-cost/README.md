# 렌더 시간은 무엇에 비례하나

렌더 한 편이 47초나 걸리던 이유를 찾으려고 쟀습니다.
**CPU 가 느려서가 아니라 그리는 장이 많아서**였습니다.

## 돌리는 방법

AI 런타임 이미지만 있으면 됩니다. **모델 서버(TorchServe)는 필요 없습니다** —
Meta 예제 캐릭터를 쓰니 관절을 찾을 일이 없습니다.

```powershell
# 저장소 뿌리에서
docker compose build ai
docker run --rm -v "${PWD}:/w" drawtale-ai-ai:latest python /w/experiments/render-cost/measure.py
```

5분쯤 걸립니다 (네 번 렌더합니다).

## 2026-10-20 에 나온 값 (20코어 PC)

| 그린 프레임 | 걸린 시간 |
|---|---|
| 37 | 6~8초 |
| 237 | 11.4초 |
| **839** | **30.6초** |

→ **고정 5초 + 프레임당 0.03초**

고정 5초는 그물 만들기 · 그래픽 초기화 · 영상 인코딩처럼 프레임 수와 상관없는 몫입니다.

## 그래서 무엇이 문제였나

서비스가 쓰는 동작 두 개가 이렇습니다 (`runtime/ai_server/motions/`).

| 동작 | 그리는 구간 | 길이 |
|---|---|---|
| `wave_hello_gentle` | 0 → 839 | **28초** |
| `jumping_gentle` | 150 → 654 | **17초** |

이야기 한 장면에 28초를 틀 일이 없는데 **처음부터 끝까지 그리고 있었습니다.**
장면에 쓸 3초(90프레임)만 그리면 **8초 안팎**입니다.
동작 설정 파일의 `start_frame_idx` · `end_frame_idx` 두 숫자를 바꾸는 일입니다
(BVH 파일을 자를 필요는 없습니다).

**다만 구간은 눈으로 골라야 합니다.** 손 흔드는 대목이 가운데에 있으면
앞 3초만 남기면 가만히 서 있는 영상이 나옵니다.

줄이는 방법 네 가지와 줄지 않는 몫은
[12 AI 아키텍처 4장](https://github.com/seominji58/drawtale-pt_docs/blob/main/12-ai-architecture.md)
에 적었습니다.

- 15fps 로 낮췄을 때 어색한지 눈으로 보기
