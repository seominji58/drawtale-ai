# 관절 인식 정확도 실험 기록

> 작성: 2026-09-29 · Backend & Cloud
> 목적: 애니메이션에서 캐릭터가 휘어 보이는 원인을 찾고, 개선 방법을 검증한다.

---

## 1. 문제

사용자가 올린 그림으로 애니메이션을 만들면 **팔다리가 원본보다 구부러져 보인다.**

원인은 AI가 찍은 관절 위치가 실제 신체 부위와 어긋나기 때문이다.
Meta AnimatedDrawings는 관절을 기준으로 그림을 늘리고 구부려 동작에 맞추므로,
관절이 어긋나면 변형이 커진다.

**근본 원인:** Meta 모델은 사람 사진으로 학습되어, 머리가 크고 팔다리가 짧은
4등신 캐릭터 그림에는 잘 맞지 않는다.

---

## 2. 실험 대상

테스트 그림 7종으로 분석 성공 여부를 먼저 확인했다.

| 그림 종류 | 관절 인식 | 마스크 |
|---|---|---|
| 선만 있는 그림 | ✅ | ✅ |
| 색칠한 그림 | ✅ | ✅ |
| 뭉뚱그린 살 형태 | ✅ | ✅ |
| 얇은 선 | ✅ | ✅ |
| 회색 배경 | ✅ | ⚠️ 배경과 캐릭터 밝기가 비슷하면 실패 |
| 종이 사진 느낌 (얼룩) | ✅ | ✅ |
| 선이 끊긴 그림 | ✅ | ✅ (수정 후) |

**관절 인식(15개 반환)은 모든 경우에 성공**한다. 문제는 위치 정확도다.

---

## 3. 시도한 방법과 결과

### 3-1. AI(GPT-4o)에게 "어디가 틀렸는지" 묻기

관절을 그림 위에 그린 이미지를 보내고 문제를 지적하게 했다.

| 항목 | 결과 |
|---|---|
| 응답 시간 | 4.5초 |
| 토큰 | 약 1,270개 (1장당 약 10원) |
| 정확도 | ✅ **높음** |

AI가 지적한 내용이 사람이 눈으로 본 것과 일치했다.

- 목이 얼굴에서 너무 위에 있음
- 양손이 팔 끝보다 안쪽에 있음
- 양발이 다리 끝보다 위에 있음

**결론: AI의 "판단" 능력은 쓸 만하다.**

### 3-2. AI가 알려준 방향으로 관절 옮기기

`up`, `down`, `up-left` 같은 방향 정보로 관절을 이동시켰다.

| 관절 | 결과 |
|---|---|
| 목 | ✅ 머리 위로 올바르게 이동 |
| 양손 | ✅ 팔 끝 쪽으로 이동 |
| 오른발 | ❌ 다리를 지나 **몸통 한가운데**로 이동 |
| 왼발 | ❌ **반대쪽 다리**로 건너감 |

**결론: 방향만으로는 정확한 위치를 찾을 수 없다.**
발에서 위로 가면 다리를 지나 몸통까지 이어져 있어 엉뚱한 곳에 도달한다.

### 3-3. AI에게 격자 칸으로 위치 묻기

그림 위에 12×12 격자를 그려 보내고 "왼손은 H6" 형태로 답하게 했다.

| 항목 | 결과 |
|---|---|
| 응답 시간 | 2.5초 |
| 정확도 | ❌ **낮음** |

관절 전체가 한쪽으로 치우쳤고, 발이 몸 밖으로 나갔다.
답이 일정한 간격의 격자 패턴(E4-E6-E8)이라 실제로 그림을 본 결과로 보기 어렵다.

**결론: 언어 모델은 픽셀 단위 위치를 정확히 짚지 못한다.**

> 주의: 처음에는 프롬프트에 예시 값을 넣었더니 AI가 예시를 그대로 따라 답했다.
> 예시는 빼고 물어야 한다.

### 3-4. 로직만으로 팔다리 끝 찾기 (AI 없이)

마스크 모양에서 몸통 중심에서 멀리 뻗은 지점을 찾아, 손·발 관절을 그쪽으로 옮겼다.
(`output/fit_joints.py`)

| 관절 | 이동 거리 |
|---|---|
| 오른손 | 22px |
| 왼손 | 27px |
| 오른발 | 19px |
| 왼발 | 4px |

관절이 실제 팔다리 끝에 가깝게 이동했고, 몸 밖으로 나가는 문제도 없었다.

**하지만 애니메이션 결과는 눈에 띄는 차이가 없었다.**

---

## 4. 결론

| 방법 | 판단 |
|---|---|
| AI에게 문제 지적 요청 | 정확하지만, 그 정보로 위치를 고치는 게 어려움 |
| AI에게 좌표·격자 요청 | 부정확. 사용 불가 |
| 로직 기반 끝점 보정 | 동작하지만 **효과가 작음** |

**손·발 관절을 20~30px 옮기는 것으로는 결과가 개선되지 않는다.**

더 큰 문제는 **몸통 쪽 관절**이다. 어깨가 가슴 한가운데에, 목이 얼굴 안에 찍히는데,
이 부분이 애니메이션 변형에 훨씬 큰 영향을 준다. 이건 모델 자체의 한계라
후처리로 해결하기 어렵다.

---

## 5. 대응 방향

| 방법 | 내용 | 판단 |
|---|---|---|
| **① 현재 수준으로 진행** | 다소 휘어도 캐릭터가 움직이는 것 자체가 결과물 | **현실적** |
| **② A2 모델 교체 대기** | 손그림 전용 Pose 모델로 근본 해결 | **원래 계획** |
| ③ 관절 보정 계속 개선 | 시간 대비 효과 불확실 | 보류 |

**①로 진행하면서 ②를 기다리는 것을 권한다.**
아이들에게는 "내 그림이 움직인다"는 경험 자체가 핵심이고,
현재 수준에서도 캐릭터를 알아볼 수 있다.

### 사용자 직접 보정에 대하여

원래 설계에는 "Frontend에서 관절을 끌어서 수정"하는 기능이 있다.
다만 **대상이 발달장애 아동이라 관절 15개를 정확히 끄는 조작은 어렵다.**

대안:

- 보호자·선생님이 대신 수정
- 동작 2~3개로 만들어 보여주고 **아이가 마음에 드는 것을 고르기**
  (고르는 조작은 아동도 가능하고, 참여감도 생긴다)

이 부분은 기획 판단이 필요하다.

## 6. 동작별 변형 정도

같은 그림으로 동작 5종을 만들어 비교했다. (`output/motions.png`)

| 동작 | 형태 유지 | 비고 |
|---|---|---|
| `jumping` | ✅ 가장 좋음 | 팔이 몸 옆에 있어 변형이 적다 |
| `jumping_jacks` | ✅ 좋음 | 팔이 아래로 내려가 안정적 |
| `wave_hello` | ⚠️ 보통 | 팔을 앞으로 모아 변형이 생긴다 |
| `dab` | ⚠️ 보통 | 팔이 크게 휜다 |
| `zombie` | ❌ 나쁨 | 몸이 기울고 형태가 깨진다 |

원본 자세(팔 벌림)와 동작 자세의 차이가 클수록 변형이 심하다.

기본 동작을 `jumping`으로 바꾸면 형태는 잘 유지되지만,
"인사"가 기본인 것이 서비스 흐름상 자연스러워 현재는 `wave_hello`를 유지한다.

## 7. 재현 방법

```bash
# AI 서버 실행
docker compose up -d

# 애니메이션 생성
python output/render.py output/source.png wave_hello

# 관절 확인
python output/draw_joints.py output/source.png output/joints.json output/check.png

# 관절 보정 실험
python output/fit_joints.py output/joints.json output/mask.png output/joints_fitted.json
python output/render.py output/source.png wave_hello output/joints_fitted.json
```
