# DrawTale 실행 · 테스트 가이드

> 작성: 2026-09-28 · Backend & Cloud
> 대상: 팀 전체 (Backend, AI, Frontend)

Backend 서버와 AI 서버를 각각 띄우고, 업로드부터 애니메이션까지 확인하는 방법을 정리한다.

---

## 0. 전체 구조

```text
Frontend (아직 없음)
    │
    ▼
Backend  127.0.0.1:8000        drawtale-backend (.venv + uvicorn)
    │                          └ DB: Azure drawtale_dev
    ▼
AI 서버  127.0.0.1:8001        drawtale-ai (Docker: ai 컨테이너)
    │
    ▼
TorchServe 127.0.0.1:8080      drawtale-ai (Docker: torchserve 컨테이너)
                               └ Meta 모델 2개 (캐릭터 검출 / 관절 추정)
```

| 서버 | 포트 | 실행 방식 | 역할 |
|---|---|---|---|
| Backend | 8000 | `.venv` + uvicorn | 업로드, DB, Job 관리, 이야기 생성 |
| AI 서버 | 8001 | Docker | 그림 분석 요청 처리 |
| TorchServe | 8080 | Docker | Meta 모델 실행 |

**AI 서버를 먼저 띄우고 Backend를 띄운다.**

## 1. AI 서버 실행 (drawtale-ai)

### 1-1. 사전 준비

- Docker Desktop 실행
- 첫 실행이라면 이미지 빌드 필요 (30~60분). 이미 빌드했으면 건너뛴다.

```bash
cd C:\Users\USER\drawtale\drawtale-ai
docker compose build
```

### 1-2. 실행

```bash
cd C:\Users\USER\drawtale\drawtale-ai
docker compose up -d
```

TorchServe가 모델을 메모리에 올릴 때까지 **1~2분** 걸린다. 상태 확인:

```bash
docker compose ps
```

`torchserve`가 `healthy`가 되면 준비 완료다.

### 1-3. 확인

| 주소 | 정상 응답 |
|---|---|
| http://127.0.0.1:8080/ping | `{"status": "Healthy"}` |
| http://127.0.0.1:8001/internal/v1/health | `{"status":"ok","model_loaded":true,...}` |
| http://127.0.0.1:8001/docs | Swagger 화면 |

`model_loaded`가 `true`여야 분석이 된다. `false`면 TorchServe가 아직 준비 중이다.

### 1-4. 종료

```bash
docker compose down
```

## 2. Backend 서버 실행 (drawtale-backend)

### 2-1. 사전 준비 (처음 한 번만)

```powershell
cd C:\Users\USER\drawtale\drawtale-backend
```

`.env`의 `DATABASE_URL`을 Azure 공유 DB 주소로 바꾼다. (비밀번호는 `C:\Users\USER\tools\secrets\drawtale-azure-db.env` 참고)

### 2-2. 실행

```powershell
cd C:\Users\USER\drawtale\drawtale-backend
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --reload
```

### 2-3. 확인

| 주소 | 정상 응답 |
|---|---|
| http://127.0.0.1:8000/health | `{"status":"ok","env":"local"}` |
| http://127.0.0.1:8000/docs | Swagger 화면 |

### 2-4. Mock AI / 실제 AI 전환

`.env` 파일에서 바꾼다. **바꾼 뒤 Backend를 재시작해야 적용된다.**

```env

# 실제 AI 서버 연결
AI_USE_MOCK=false
AI_SERVICE_URL=http://127.0.0.1:8001
```

## 3. 분석 테스트 (업로드 → 관절 15개)

### 3-1. AI 서버만 테스트 (가장 간단)

1. http://127.0.0.1:8001/docs 접속
2. `POST /internal/v1/analyze` 클릭 → **Try it out**
3. **Choose File**로 사람 그림 선택 → **Execute**
4. 아래 Response에 결과 확인

**정상 응답 예시**

```json
{
  "success": true,
  "bbox": { "left": 338, "top": 190, "right": 1602, "bottom": 1434 },
  "joints": [ { "name": "hip", "x": 1002, "y": 1100 }, "... 15개" ],
  "mask": { "width": 1264, "height": 1244 },
  "model_version": "meta-animated-drawings-pretrained",
  "coordinate_space": "image_px",
  "processing_time_ms": 3158
}
```

**확인할 점**
- `joints`가 15개인지
- 좌표가 **올린 그림의 원본 크기 안**에 들어가는지 (2000px 그림이면 좌표도 2000 이하)
- `processing_time_ms`가 3000~5000 정도인지

### 3-2. Backend 통해서 테스트 (실제 서비스 흐름)

`.env`에서 `AI_USE_MOCK=false`로 두고 Backend를 재시작한 상태여야 한다.

1. http://127.0.0.1:8000/docs 접속
2. `POST /api/v1/characters` → **Try it out** → 그림 선택 → **Execute**
3. 응답의 `character_id`, `job_id`를 복사
4. `GET /api/v1/jobs/{job_id}`로 상태 확인 — `succeeded`가 될 때까지 반복 (3~5초)
5. `GET /api/v1/characters/{character_id}`로 결과 확인

**확인할 점**
- Job `status`가 `succeeded`
- `analysis.bbox`가 `x/y/width/height` 형식 (AI의 `left/top/right/bottom`에서 변환됨)
- `joints` 15개
- `joints_corrected`가 `false` (아직 사용자가 수정 안 함)

### 3-3. 에러 테스트

사람이 없는 그림(빈 사각형 등)을 올린다.

- Job `status`가 `failed`
- `error.code`가 `NO_CHARACTER_DETECTED`
- `error.message`가 한국어 안내 문구

## 4. 애니메이션 테스트 (현재 상태)

> **현재 `POST /internal/v1/render`는 구현되지 않았다.**
> 아래는 Meta 원본 코드로 애니메이션이 만들어지는지 확인하는 방법이다. (2026-09-28 검증 완료)

### 4-1. 검증된 사실

화면 없는 Docker 환경에서도 애니메이션 렌더링이 된다. 다음 조건이 필요하다.

| 항목 | 값 |
|---|---|
| 렌더링 방식 | Meta 설정에서 `view: {USE_MESA: True}` |
| 시스템 라이브러리 | `libosmesa6`, `ffmpeg` |
| Python 라이브러리 | PyOpenGL, **scikit-learn**, shapely, scikit-image, opencv, PyYAML, tqdm |
| 출력 형식 | **GIF로 렌더링 후 ffmpeg으로 MP4 변환** |

> OpenCV에 H.264 인코더가 없어 MP4 직접 생성은 실패한다.
> GIF(10MB) → MP4(452KB)로 변환하면 파일도 훨씬 작아진다.

### 4-2. 직접 확인하는 방법

**① 테스트용 이미지 빌드** (`C:\Users\USER\tools\rendertest\Dockerfile`)

```dockerfile
FROM python:3.10-slim-bookworm
RUN apt-get update && apt-get install -y --no-install-recommends \
    libosmesa6 libgl1 libglib2.0-0 ffmpeg \
    && rm -rf /var/lib/apt/lists/*
RUN pip install --no-cache-dir \
    numpy==1.24.4 scipy==1.10.0 scikit-image==0.19.3 \
    opencv-python-headless==4.10.0.84 Pillow==10.1.0 \
    PyOpenGL==3.1.6 PyYAML==6.0.1 shapely==1.8.5.post1 tqdm==4.66.3 scikit-learn==1.1.2
WORKDIR /work
```

```bash
cd C:\Users\USER\tools\rendertest
docker build -t render-test:latest .
```

**② 렌더링 스크립트** (`C:\Users\USER\tools\rendertest\run.py`)

```python
import sys, yaml
from pathlib import Path
sys.path.insert(0, '/work/AnimatedDrawings')

char_dir = Path('/work/AnimatedDrawings/examples/characters/char1')
mvc = {
    'scene': {'ANIMATED_CHARACTERS': [{
        'character_cfg': str(char_dir / 'char_cfg.yaml'),
        'motion_cfg': '/work/AnimatedDrawings/examples/config/motion/wave_hello.yaml',
        'retarget_cfg': '/work/AnimatedDrawings/examples/config/retarget/fair1_ppf.yaml',
    }]},
    'controller': {'MODE': 'video_render', 'OUTPUT_VIDEO_PATH': '/work/out/video.gif'},
    'view': {'USE_MESA': True},
}
Path('/work/out').mkdir(exist_ok=True)
cfg_path = '/work/out/mvc_cfg.yaml'
with open(cfg_path, 'w') as f:
    yaml.dump(mvc, f)

import animated_drawings.render
animated_drawings.render.start(cfg_path)
print('렌더링 완료')
```

**③ 실행**

```bash
cd C:\Users\USER\drawtale\drawtale-ai
docker run --rm ^
  -v "//c/Users/USER/drawtale/drawtale-ai/third_party/AnimatedDrawings://work/AnimatedDrawings:ro" ^
  -v "//c/Users/USER/tools/rendertest://work/test" ^
  -w //work render-test:latest sh -c "mkdir -p /work/out && cp /work/test/run.py /work/ && python run.py && ffmpeg -y -i /work/out/video.gif -movflags faststart -pix_fmt yuv420p -vf 'scale=trunc(iw/2)*2:trunc(ih/2)*2' /work/out/video.mp4 && ls -la /work/out/"
```

**정상 결과:** `video.gif`(약 10MB), `video.mp4`(약 450KB)가 생성된다.

### 4-3. render 구현 시 흐름 (앞으로 만들 것)

```text
Backend                              AI 서버 (render 구현 후)
  │ POST /internal/v1/render          │
  │ { 보정된 관절 15개, motion }  ──▶ │
  │                                   │ ① 관절 좌표로 char_cfg.yaml 생성
  │                                   │ ② mask.png, texture.png 준비
  │                                   │ ③ USE_MESA로 GIF 렌더링
  │                                   │ ④ ffmpeg으로 MP4 변환
  │ ◀── MP4 파일 또는 저장 경로 ───── │
```

**필요한 파일 3개** (Meta 캐릭터 폴더 구조)

| 파일 | 내용 |
|---|---|
| `char_cfg.yaml` | 이미지 크기, 관절 15개 좌표, 뼈대 연결 정보 |
| `texture.png` | 원본 그림 |
| `mask.png` | 캐릭터 영역 마스크 — **현재 AI 서버가 저장하지 않아 추가 필요** |

참고할 예시: `third_party/AnimatedDrawings/examples/characters/char1/`

## 5. 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `/docs`가 안 열림 | 서버가 안 떴음 | `docker compose ps` 또는 uvicorn 로그 확인 |
| `model_loaded: false` | TorchServe 준비 중 | 1~2분 기다린 뒤 다시 확인 |
| 분석 시 `MODEL_UNAVAILABLE` | TorchServe 연결 실패 | `docker compose logs torchserve` 확인 |
| Backend에서 DB 연결 실패 | 네트워크가 바뀌어 IP가 방화벽에 없음 | https://api.ipify.org 결과를 Backend 담당에게 전달 |
| Job이 계속 `running` | Backend가 DB 연결에서 멈춤 | Backend 재시작 |
| 관절 좌표가 그림보다 작음 | 예전 버전 AI 서버 | AI 이미지 재빌드 |

### 자주 쓰는 명령어

```bash
docker compose logs -f ai          # AI 서버 로그
docker compose logs -f torchserve  # 모델 서버 로그
docker stats                       # 메모리 사용량
docker compose restart ai          # AI 서버만 재시작
docker compose down                # 전부 종료
```
